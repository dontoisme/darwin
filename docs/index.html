How It Works

1

Manifest maps source to screens

Define which Swift files affect which UI screens in manifest.json

2

Git diff detects changes

Darwin checks which files changed since your last capture

3

XCUITest captures affected screens

Only the screens that could have changed are re-captured

4

Review what changed

Browse in the viewer, or feed structured diffs to your AI for automated review.

How It Works

What your AI assistant does
# 1. Runs darwin init, presents options in native UI
darwin init --ai-interactive

# 2. Detects all your SwiftUI screens
darwin detect --add

# 3. Writes test navigation logic for each screen
# 4. Captures baseline screenshots
darwin capture --baseline

# 5. Opens the visual timeline
darwin viewer

After setup, Darwin auto-captures after every commit. Just code—Darwin watches.

Use Cases

AI-assisted development — Your AI added a settings screen. Did it accidentally break the home view? Darwin shows you.
Solo builder sanity check — No QA team? No problem. Automated visual history keeps you honest with yourself.
Visual regression testing — Catch unintended UI changes before they ship.
Design review — Generate visual diffs for PR reviews or async feedback.
Development timelapse — Build a visual history of your app's evolution. Great for demos and retrospectives.
